# 多 AI 分工與交接（us-guide）

## 原則

- GitHub 是唯一正本；電腦與各 AI 對話都是可丟棄的。
- 金鑰、權杖、帳號、持倉資料一律不寫進 repo、文件或回覆。
- 不編造數字與功能。資料不足就寫「無法判斷」。
- 所有說明文字用繁體中文；ticker、指標名、skill id、檔名與指令保留英文原樣。
- 每份輸出都不給買賣建議；需要結論時加「資訊整理，非投資建議」。

## 角色

| AI | 做什麼 | 不做什麼 |
|---|---|---|
| Claude | 架構、產生器與後端、看板頁面、審稿、整合、有疑義時裁決 | 機械性大量翻譯（交給 Gemini） |
| Gemini（網頁版或 Jules） | 繁中說明與流程翻譯、前端細節（依任務單） | 改動 `scripts/build_guide.py` 的邏輯、改上游檔案 |
| ChatGPT | 名詞對照、第一週閱讀路線翻譯、抽樣校對 | 寫程式、改任何 `.py`／`.html`／`.json` 結構 |

## 工作流程

1. 任務單在 `us-guide/tasks/`，一個任務一個檔，包含輸入、輸出、驗收條件。
2. 一家 AI 開分支（`gemini/<任務編號>` 或 `chatgpt/<任務編號>`），只改任務單列出的檔案，開 PR，標題寫明是哪家 AI。
3. 不能連 GitHub 的 AI：把結果貼回對話，由使用者或 Claude 代為提交。
4. Claude 審稿：先列「違反任務單範圍的地方」，再列「事實或格式錯誤」，最後才是風格。通過後使用者合併。
5. 不直接推 main。

## 驗收通用條件

- `python3 us-guide/scripts/build_guide.py` 能跑完且 JSON 合法。
- 不改動 `skills/`、`docs/`、`workflows/` 等上游目錄。
- 沒有新增任何金鑰、個資或絕對路徑。
