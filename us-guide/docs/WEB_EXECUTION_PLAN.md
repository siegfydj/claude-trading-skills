# 在網頁上執行全部美股 skill：規劃

狀態：規劃稿，尚未實作執行層。目前只有唯讀看板（`index.html`）。

## 1. 目標

使用者希望把上游 74 個 skill 都能在網頁上「呈現並使用」。本文件把「使用」拆成可驗證的階段，說明每個階段需要什麼、風險在哪。

## 2. 先講清楚：skill 的「執行」是什麼

- 每個 skill 的 `SKILL.md` 是寫給 Claude 的工作指令；`scripts/` 只負責取資料、計算、產生報告。
- 所以「執行一個 skill」有兩種形態：
  1. 只跑腳本（取資料＋計算＋輸出 JSON／Markdown）。網頁後端可以做。
  2. 需要 Claude 依指令搜尋、看圖、判讀。網頁要做就得呼叫 LLM API（付費）。
- 74 個 skill 中，只有 3 個沒有腳本（market-news-analyst、scenario-analyzer、us-stock-analysis），但另有 6 個因為必須讀網頁、SEC 文件或圖表，也需要 LLM。

## 3. 可行性分級（由 `build_guide.py` 自動判定，來源 `skills-index.yaml`）

| 層級 | 定義 | 交易用 skill 數 | 網頁執行需要 |
|---|---|---|---|
| A | 純計算，可離線；部分有選用金鑰加強功能 | 38 | 後端跑腳本；少數可改寫成瀏覽器內計算 |
| B | 讀公開資料，免付費金鑰 | 4 | 後端排程抓資料再算；注意對方網站條款與穩定度 |
| C | 必須有付費金鑰（FMP／FINVIZ／Alpaca） | 19 | 後端保管金鑰；處理額度、費用、速率限制 |
| D | 需要 LLM 判讀（網搜／圖表／無腳本） | 9 | LLM API 費用與品質控管 |

統計包含非股票與期貨類 skill（約 8 個），看板預設會隱藏它們。層級是依索引自動判斷，個別 skill 仍需實測確認（例如 portfolio-manager 在索引中標示 Alpaca 為選用，但上游 core-portfolio-weekly 流程標為 alpaca-required）。

## 4. 建議架構

```
瀏覽器（靜態看板＋表單）
   │  HTTPS＋登入驗證
   ▼
薄後端（白名單 API：POST /run { skill, args }）
   │  只允許 skills-index.yaml 列出的腳本與參數
   ▼
執行器（Python 子程序，逾時、記憶體上限、一次一個工作）
   │  金鑰只存在後端環境變數
   ▼
reports/ 與 state/（私有儲存，不進 git）
```

原則：

- 金鑰永遠不進瀏覽器、不進 repo。fork 是公開 repo。
- 後端不接受任意指令，只接受白名單 skill 與預先定義的參數。
- 持倉、交易紀錄（trader-memory-core 的 thesis YAML）屬於個人資料，存後端私有位置，不放 GitHub。
- 只有使用者一人使用時，登入驗證用簡單方案即可，但不能省略：沒有驗證的公開端點會被拿去耗盡 FMP 額度。

## 5. 執行環境選項

| 選項 | 優點 | 缺點 |
|---|---|---|
| 自有 Oracle 主機（tw-engine 已使用，規格 E2.1.Micro，1 GB 記憶體＋2 GB swap） | 免費、已有部署習慣 | 記憶體緊；與台股資料引擎共用會互相影響，建議獨立排程且限制一次一個工作，或另開一台 |
| GitHub Actions 當執行器 | 不用維護主機 | 網頁無法安全觸發（需要 token）；結果取回麻煩；排程用量有上限 |
| 只在本機 Claude Code／Claude 網頁版執行，網頁僅閱讀 | 最安全、成本最低 | 不符合「網頁上使用」 |

建議：先用「獨立的小型後端＋一次一個工作」，不要與 tw-engine 共用程序。實際主機規格以你當前環境為準，動工前需要你確認。

## 6. 分階段實作

| 階段 | 內容 | 需要金鑰 | 狀態 |
|---|---|---|---|
| P0 | 唯讀看板：分類、篩選、流程、層級、金鑰說明 | 否 | 已完成（v0，英文原文為主） |
| P1 | 繁中說明完整填入；新增「台灣時間對照」（美股開盤時段換算成台北時間，含夏令／冬令切換） | 否 | 待 Gemini 翻譯 |
| P2 | A 層離線小工具：先做 position-sizer 的瀏覽器版（純計算，不需後端）；評估其他 A 層是否值得改寫 | 否 | 規劃 |
| P3 | 後端執行器：先開放 A、B 層；產出報告在網頁顯示與下載 | 否 | 規劃，需決定主機 |
| P4 | C 層：FMP 等金鑰放後端；先量測每個 screener 單次呼叫量，再決定哪些能在免費額度內跑 | 是 | 尚未量測，不估算 |
| P5 | D 層：建議維持在 Claude 對話內執行，網頁只負責貼結果與保存。若要在網頁內呼叫 LLM API，另做成本評估 | 是（付費 API） | 建議不做 |

每個階段完成後才開下一個。P4 之前不做任何付費 API 呼叫。

## 7. 風險與限制

- 上游會持續自動更新 skill（有每日自動改進與產生新 skill 的流程）。同步上游後要重跑 `build_guide.py`，並重新檢查分級。
- 上游多數 skill 的驗證欄位為 `not_verified`；網頁執行不會讓結果變可靠，只是方便。每份輸出都要附「資訊整理，非投資建議」。
- 部分 skill 的輸出彼此串接（例如 breakout-trade-planner 吃 vcp-screener 的輸出），所以 A 層 skill 實際上可能依賴 C 層 skill 先跑完。執行器要處理上下游相依。
- 美股資料條款：FMP、FINVIZ、Alpaca、TraderMonty 公開 CSV 各有使用條款，公開提供給他人使用前需逐一確認；個人自用風險較低。
- 台股助手那邊的 ToAlpha MCP 條款禁止批量建庫，與本專案無關，不可把台股資料混進這裡。

## 8. 需要使用者決定

1. 執行層放哪裡：獨立小型主機、既有 Oracle 主機、或先不做（維持唯讀）。
2. 是否接受 P5 建議（D 層不做網頁版）。
3. 看板是否要用 GitHub Pages 公開（fork 為公開 repo，頁面內容只含上游公開資訊，但這是對外發布，需要你同意）。

## 9. 分工

- Claude：架構、後端與執行器、看板頁面、審稿與整合。
- Gemini：繁中說明與流程翻譯、前端細節實作（依任務單，開分支與 PR，Claude 審）。
- ChatGPT：不寫程式。只做名詞對照、第一週閱讀路線翻譯、對 Gemini 翻譯做抽樣校對。
